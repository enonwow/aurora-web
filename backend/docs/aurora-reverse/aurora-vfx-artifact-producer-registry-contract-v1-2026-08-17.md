# Aurora VFX artifact producer registry contract v1

Date: 2026-08-17

## Status and authority boundary

`aurora-vfx-artifact-producer-registry/v1` is repository control-plane
metadata. It discovers, orders, validates, and explains production of VFX gate
artifacts. It is not Aurora runtime authority, retail evidence, or parity
promotion authority.

Only a downstream evidence validator may promote a retail/parity claim. A
successful registry validation or bootstrap therefore never changes
`canonicalParityPromoted` from `false`.

## Registry shape

The canonical registry is
`backend/docs/aurora-reverse/vfx-artifact-producer-registry-v1.json` and has:

- `version`: exactly `aurora-vfx-artifact-producer-registry/v1`;
- `artifacts`: non-empty records with unique `artifactId` and `outputPath`;
- `gates`: a map from stable gate id to an ordered set of artifact ids.

Every artifact record contains:

- `artifactId`: stable identifier used by dependencies and gates;
- `schemaId`: expected content schema, or `unversioned-text/v1` when the
  format has no embedded schema field;
- `outputPath`: normalized repository-relative path using `/` separators;
- `producer.kind`: exactly one of `repository-command`,
  `tracked-repository-input`, or `external-ingestion`;
- `producer.command`: required only for `repository-command`; it must contain
  an explicit `--out`/equivalent argument naming `outputPath`;
- `producer.resumeCondition`: required for `external-ingestion` and must say
  what authoritative external event/file unblocks the artifact;
- `inputs`: artifact ids that must validate before this artifact is produced;
- `sourceClass`: low-cardinality source classification;
- `freshness`: versioned freshness mode and, where applicable, dependency
  hash policy;
- `validation.format`: `json`, `jsonl`, or `markdown`;
- `validation.versionField` and `validation.expectedVersion` when embedded
  schema validation is available;
- `retailEvidence`: boolean. Registry metadata itself never proves this flag.

## Structural validation

The registry validator fails closed when:

1. the registry is not a regular UTF-8 JSON file;
2. its version or record shape is wrong;
3. artifact ids or output paths are duplicated;
4. an input or gate references an unknown artifact;
5. dependency edges contain a cycle;
6. a consumed artifact has no producer classification;
7. a repository producer omits an explicit registered output path;
8. a tracked/external input incorrectly declares a repository command;
9. an external input omits its precise resume condition;
10. a path is absolute, escapes the repository, or is not normalized.

Validation emits stable error codes and never leaks a raw parser or filesystem
stack as the user-facing result.

## Artifact validation

An artifact is present only when `lstat` confirms a regular file. Directories,
links, devices, and other filesystem entries are invalid prerequisites.

For JSON, the complete file must parse and the configured version field must
match. For JSONL, every non-empty line must parse independently and the file
must contain at least one record. Markdown must be a non-empty regular UTF-8
file. A validated artifact records byte length and SHA-256.

Malformed, wrong-version, stale, or non-regular artifacts are reported in
`invalidPrerequisites`; absent files are reported in `missingPrerequisites`.
Neither class may fall through to a consumer's raw `readFile`/`JSON.parse`.

## Bootstrap behavior

`vfx:control-plane:bootstrap` has two modes:

- dry-run (default): topologically plans actions and performs no writes or
  producer execution;
- `--execute`: validates existing artifacts, runs eligible repository
  producers in dependency order, then validates the exact registered output.

The plan is deterministic for identical registry and filesystem state. It
contains no wall-clock timestamp in its digest. Execution stops at the first
failed producer, missing output, wrong-path output, invalid artifact, or
external semantic blocker. A zero exit code without the registered regular
output is `producer_output_missing`, not success.

Tracked inputs are never synthesized. External coordinator/director reports
are never generated by this repository: bootstrap reports the registered
resume condition and keeps all promotion fields false.

## Compatibility and migration

The previous inline prerequisite arrays remain readable only during migration.
After each gate is migrated, the registry is the only source for producer,
path, dependency, schema, and recovery-command metadata. CLI path overrides
are test/operator inputs and are validated using the same artifact contract;
they do not mutate the canonical registry.
