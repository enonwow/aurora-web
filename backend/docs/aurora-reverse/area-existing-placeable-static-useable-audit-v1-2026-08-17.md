## Frozen mutation contract

Area detail already preserves explicit boolean members under
`placeableMetadata.static` and `placeableMetadata.useable`. Each member remains
presence-sensitive. A missing member never becomes writable provenance, even
though the read model may derive a presentation-only static fallback from an
explicit `Useable` value.

The frontend retains explicit source values independently as
`source.placeableStatic` and `source.placeableUseable`. Editable values remain
`object.isStatic` and `object.placeableProperties.useable`. A mutation contains
only source/target pairs whose values differ. It may be combined with the
already admitted `OnUsed` mutation for the same immutable object.

The backend resolves the immutable `Placeable List` ordinal and replaces only
the selected fields:

```text
Placeable List[sourceIndex].Static  : Byte = boolean target
Placeable List[sourceIndex].Useable : Byte = boolean target
```

For every selected field, the writer requires exactly one native byte, verifies
the source byte against retained provenance, writes `0` or `1`, and preserves
every other field. It does not enforce an inverse relationship. Property-only
publication keeps GIC byte-identical. Independent candidate readback verifies
all changed fields and complete preservation of the remaining struct.

## Fail-closed and completion gates

The operation fails closed for missing provenance, absent/duplicate/wrongly
typed native fields, non-boolean source/target values, unchanged pairs,
unsupported families, duplicate object mutations, deletion collisions, stale
source bytes, or readback drift. Diagnostics identify the bounded placeable
ordinal and field name without exposing raw bytes, tags, scripts, or host paths.

Implementation completion requires contract and parser/mapper presence tests,
projector/planner rejection tests, exact GIT-only rewrite and readback tests,
combined-field/combined-`OnUsed` tests, frontend port/facade/UI guard tests,
integration and build gates. Mutation testing for changed critical logic is
optional and requires an explicit user request. Product completion still requires a fresh exact
Aurora Web candidate to pass Toolset Save/Build/reopen and NWN proof.
