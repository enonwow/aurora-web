## Statusy dojrzalosci

| Status | Znaczenie |
| --- | --- |
| `screen-supported` | Operacja jest widoczna w screenach/manualach, ale nie byla jeszcze odtworzona w live Toolsecie. |
| `opened-live` | Otworzylismy dialog/edytor/palette w live Toolsecie, ale nie wykonano jeszcze bezpiecznej mutacji. |
| `mutated-live` | Wykonano mutacje w live Toolsecie, ale nie ma jeszcze pelnej weryfikacji po ponownym otwarciu albo powtorce. |
| `verified-after-reopen` | Mutacje potwierdzono po zamknieciu i ponownym otwarciu properties/dialogu. |
| `safe-repeatable` | Atom ma znana bezpieczna sekwencje, dowody i pulapki; moze byc skladnikiem wiekszego workflow. |
| `gap` | Wiemy, ze operacja jest potrzebna, ale nie mamy niezawodnej sciezki. |

## Zasady bezpieczenstwa

- Nie przejmowac globalnego kursora uzytkownika.
- Nie uzywac globalnego `SendKeys`.
- Nie uzywac globalnych dragow/klikow, jesli da sie celowac w konkretny HWND.
- Nie uzywac `UIAutomationClient` / `ValuePattern` na VCL polach Toolsetu jako
  standardowej metody inputu; w HB-S19 doprowadzilo to do ghost window.
- Nie zapisywac modulu bez osobnej zgody uzytkownika.
- Screenshot jest dowodem tylko wtedy, gdy realnie pokazuje czytelny Toolset
  albo wlasciwy dialog. Jesli ekran jest ciemny/pusty/nieczytelny, atom nie
  moze byc zaliczony jako live.
- Dla propertiesow, conversation editorow i innych wielozakladkowych okien
  robic serie screenow: overview plus kazda widoczna zakladka/wiekszy panel.
- Po `Access violation` zamknac Toolset i odtworzyc znane kroki od poczatku.
- Po ghost window albo niezamykalnym dialogu przerwac atom, zrestartowac
  Toolset i wybrac `Tak` przy backup recovery.
- Nie promowac atomu do `verified-after-reopen`, jezeli nie ma ponownego
  otwarcia, screenshotu albo innego twardego dowodu.
