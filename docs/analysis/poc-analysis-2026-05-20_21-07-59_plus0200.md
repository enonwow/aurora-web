## Current State
1. Core stack is hybrid:
- Python NWN parsing/export pipeline (`exporter/`).
- Three.js + TypeScript viewer (`web/`).
2. Dev-server backend logic is embedded in Vite config (`web/vite.config.ts`) including API route handlers and Python process spawning.
3. Scene loading path is currently monolithic JSON fetch (`response.json()`, `cache: "no-store"`), with in-memory hydration/dedup.
4. Rendering optimizations already exist (instancing path and texture compression modes `none|etc1s|uastc`).
5. Test footprint is substantial (TypeScript tests and Python integration tests exist).
6. Documentation is rich and includes explicit gap tracking in `Documentation/Coverage.md`.
7. Workspace state is heavily WIP with many modified and untracked files.

## Risk Analysis
1. High payload/transfer risk: very large monolithic scene JSON files remain a direct scalability risk.
2. High architecture-coupling risk: backend behavior coupled to Vite dev plugin and runtime Python spawning.
3. Medium cache/portability risk: local absolute machine paths in config block reproducible deployments.
4. Medium data hygiene risk: large generated/local artifact footprint increases drift and accidental coupling.
5. Medium test realism risk: some regression tests are fixture-gated and may silently skip in clean environments.
6. High contract drift risk: no formal OpenAPI/JSON Schema contract gate across FE/BE yet.

## Gaps
1. Missing production-grade contract-first API for `manifest + chunks + immutable assets + deltas`.
2. Missing explicit chunk streaming protocol for heavy scenes (flow remains scene-JSON centric).
3. Missing dedicated FE/BE service split with stable deployment boundaries.
4. Missing explicit formal L1/L2 cache architecture contract.
5. Missing CI-level performance gate aligned to primary benchmark target.
6. Domain gaps still open in docs (for example minimap imagery and EE rendering edge cases).

## Recommended Next Actions
1. P0: Freeze Contract v1 with strict versioned fields and payload budgets (`catalog/build/progress/manifest/chunk/commands`).
2. P0: Separate backend from Vite plugin; keep Vite as frontend dev tool only.
3. P0: Replace monolithic scene delivery with manifest + chunked binary/object assets + immutable hashes.
4. P1: Formalize cache architecture (client bounded cache + backend L1 + durable L2 shared/object storage) and invalidation policy.
5. P1: Harden quality gates in CI (contract tests, transfer tests, regression tests, benchmark regression gate).
6. P1: Enforce workspace hygiene for deterministic fixtures and generated artifact handling.
7. P2: Close documented content gaps based on `aurora-web` scope priorities.
