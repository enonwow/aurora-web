# Native Aurora bridge scope

The separate operator-only `aurora-toolset-interrupted-open-close.mjs` route admits a documented legacy interrupted launch through a read-only dry run. It binds the preserved manifest, checkpoint, exact process creation identity, blank frame, module and ordered HAK hashes. Its separately authorized close uses only the existing canonical graceful close atom with force disabled and preserves the original unknown outcome. It emits an exclusive receipt for optional native-ledger reconciliation; it is not an MCP capability and cannot launch another process or clear a lease itself.

This extension adds a public coordinator, read-only active-Area and blank-frame observers, an exact `temp0` recovery admission library, and a durable module-open action journal for the first Aurora native adapter profile. The admitted MCP operations are limited to `sessions_list`, `session_launch`, `session_attach`, `aurora_state_get`, and `aurora_area_open`. The blank-frame observer is an operator reconciliation primitive and is not an MCP process-control route. Other authoring, save, build, Test Module, script, object, and property routes remain unavailable unless they receive separate qualification.

The MCP adapter accepts only operator-pinned Node, coordinator, Toolset, profile, bootstrap profile, direct atoms, and the complete known local dependency closure. The `session_launch` closure includes the binary geometry atom, module opener, action-journal helper, and their imported libraries; missing or drifted dependencies withdraw the capability. Calls use strict typed arguments, exact PID plus creation-time identity, bounded deadlines and output, no shell, no global input, no focus or topmost manipulation, and a minimal Windows environment with OS-derived Windows directories. Durable request reconciliation and target/global mutation leases remain in the native dispatcher. Any coordinator process that started but did not return a validated terminal response is an unknown mutation outcome and is never replayed automatically.

The canonical tooling deployment must install the versioned coordinator, observers, recovery library, and action-journal helper, then apply the ordered patches in `patches/`. The patches bound the explicit MCP cold-open route while preserving legacy timeouts for existing canonical callers. The journal records immutable intent and submitted events around native module-open actions. Exact `temp0` admission compares every bounded resource byte-for-byte, supports the canonical resource-type table including UTI and UTP, and rejects unknown resource types. The operator must recompute and configure SHA-256 pins after deployment.

Contract tests cover fixed-atom admission, fresh active-Area state, stable revisions, nested real receipt parsing, caller-budget propagation, legacy timeout preservation, PowerShell parsing, strict blank-frame titles, immutable journal behavior, and exact recovery admission. Python adapter tests cover configuration strictness, full dependency drift, bootstrap drift, bounded streaming I/O, timeout ambiguity, transport-budget admission, and service-compatible session identity.

Source review, unit tests, patch applicability checks, and deployment hashes establish configured code lineage. They do not establish an end-to-end verified MCP launch, attachment, state observation, or Area open. Live acceptance requires an operator-authorized isolated profile and separate execution and postcondition evidence.
