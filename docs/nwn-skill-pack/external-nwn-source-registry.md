# External NWN Source Registry

## Purpose

Collect source candidates for the NWN server gamedev skill pack and label their trust level. This registry is for source discovery and citation planning, not a guarantee that every linked claim is already verified.

## Trust Tiers

- `primary`: official or project-owned source for the relevant software.
- `strong-community`: widely used community reference, good for builder workflows, but still review before promotion.
- `community-example`: useful tutorial, forum, or package snapshot; never promote as general truth without cross-checking.
- `local-runtime`: direct evidence from the target module/server/runtime.

## Immediate Skill-Pack Implications

- NWScript guidance should cite NWN Lexicon first and runtime compile/test second.
- Testing/runtime QA guidance should use `neverwinter.nim` compiler docs for compile evidence, Lexicon debug helpers for vanilla runtime proof, and NWNX Core/Util docs only for NWNX-enabled servers.
- Location/area guidance should combine NWNWiki/Fandom builder constraints with NWN Lexicon runtime transition semantics.
- Creature/encounter guidance should combine NWNWiki/Fandom builder structure with NWN Lexicon event/AI semantics and runtime balance tests.
- Item/equipment/loot guidance should combine NWNWiki/Fandom item/property structure with NWN Lexicon item event, creation, inventory-fit, and item-property semantics, then require runtime economy tests.
- Economy/crafting/progression guidance should treat Lexicon money, store, experience, and item-creation functions as the scripting source lane, NWNWiki/Fandom craft pages as default Toolset behavior, and NWNX Store/SkillRanks as optional NWNX-only controls.
- Quest/dialogue/journal guidance should use NWN Lexicon conversation/journal pages for semantics, while keeping simple wiki/tutorial quest helpers as examples only.
- NUI guidance should combine Lexicon function docs with nwn.wiki's NUI system notes and runtime UI testing.
- 2DA/TLK/HAK guidance should treat Fandom/NWNWiki pages as useful structural references but require project/runtime verification before claiming a release-safe pipeline.
- Persistence guidance should separate object locals, campaign DB, built-in EE SQLite, and NWNX SQL because their dependencies and failure modes differ.
- NWNX guidance should be isolated from vanilla NWN guidance because NWNX targets server extension behavior and has its own supported-platform constraints.
- NWSync setup should cite `neverwinter.nim` README/source for tool behavior and keep Steam/forum setup guides as practical examples only.
- Deployment guidance should treat `settings.tml` as a documented config lane, but require target-server config and secrets review before release guidance.
